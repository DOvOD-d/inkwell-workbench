Word 模板工作台 v1.0.1 · 标签行固定，不再被输入撑开
======================================================

问题：“（一）选题的意义：”这类行在填了多行内容后，标签字符被拉开成
“（     一     ）    选     题    的   意    义  ：”。

原因：这段用的是“两端对齐”（任务书里 Normal 样式就是两端对齐）。填写值里的换行是
同一段内的软换行，Word 会把非末行拉满整行；首行带着标签，于是标签字符被均匀撑开。
不是识别或字体设置的问题。

修法：
· 只针对“标签 + 值在同一段、且值里有多行”的段落，把该段固定为左对齐；
  标签和首行不再被两端对齐拉开，基线、字号、行距、缩进都不变。
· 单行内容（没有换行）的段落保持原来的两端对齐，不改模板观感。
· 正文类纯段落（没有标签前缀）也保持原对齐方式。

验证：
· 任务书“（一）选题的意义：短句。\n第二段…”：生成件该段 jc=left，渲染后标签正常，
  第二行正常换行；“（二）创新性：”单行仍保持两端对齐。
· 预览与生成走同一逻辑，实时预览里看到的就是最终效果。
· 文本框清理、超页提醒、模板要求与输入框字号规则均无回归。
· 内置 4 模板冒烟 ok、OOXML 自检 0 问题；pyflakes 全模块 0 问题。

Word 模板工作台 v5.22.0 · 识别改为「结构 + 文本模型」
======================================================

这一版重做识别链路：不再把 Word 页面截图交给视觉模型去“看”栏目。
位置由 OOXML 结构决定，栏目名/分组/单行还是多行由文本模型通读整份文档结构决定；
视觉模型只在少数栏目有分歧时，看涉及的那 1–3 页截图做复核。

1）为什么改
   · 截图把版面压成像素，合并单元格、下划线、空单元格全靠模型猜；模型给的列坐标经常
     指到左边的标签格，同一页里还会把标题行、表头当成栏目。位置一错，写进去就是错。
   · .docx 自己就带着段落、表格、合并关系、下划线和占位符。把这层结构原样交给文本模型，
     模型只需要判断“这一格空着、该叫什么”，定位由程序按原文精确回填，错不了。

2）识别怎么分工（新增 textparse.py）
   · 结构清单：把每个段落、每个表格单元格（含合并信息）、下划线、连续空白、{{占位符}}
     和空单元格序列化成“坐标 :: 原文”的清单。
   · 切块：按空位数量切片，每片最多 24 个空位，保证模型输出不超长；某片返回的 JSON
     不完整会自动二分重试；大文档最多问 10 片。
   · 严格校验：坐标必须存在且非负；标签必须在该段落/该行原文里出现；单元格必须是空的
     或含空位标记（表头“姓名/出生年月”这类短格子不会被当成值格）；签名、盖章、说明、
     示例一律不接收；置信度低不采纳。
   · 合并：结构结果永远是位置的唯一来源。文本模型只做三件事——改栏目名（仅当结构名是
     “填写项/字段N”这类通用名时）、补分组、把“单行”纠正为“多行/日期/数字/选择”。
     它提出的新栏目必须在原文里用标签定位到具体空位，定位不到就丢弃。
   · 模型不可用、超时、返回乱码：保留结构识别结果，照常往下走，不会卡住识别。

3）少量截图复核（visionparse.verify）
   · 只有“模型读出的名字与结构不一致”或“模型说有、结构里定位不到”的少数栏目才会触发。
   · 先查 PDF 文字层，只渲染含这些栏目文字的那几页（最多 3 页），不再整篇截图。
   · 复核只用来改栏目名和类型；视觉说“不存在”也不会删掉结构识别出的位置。
   · 视觉模型没配置（Key 为空）时自动跳过，并在结果里注明。

4）顺带修掉的三类识别缺陷
   · 栏目名被截掉右括号：“经费总额（元）”以前变成“经费总额（元”，项目任务书里 7 个字段名残缺；
     现在只有整段被括号包住时才去括号。
   · 小节标题被当栏目：“一、实验目的”“二、实验设备及环境”这类标题已有正文，写入范围会覆盖
     原文示例，现在一律不当栏目。
   · 图片插入点被当文本栏目：“第N题运行结果的截图如下：”这种没有文字空位的占位不再生成栏目。

5）实测数据（本机 Ollama qwen3:4b-instruct，示例目录 3 份 + 内置模板 4 份）
   结构识别（不含模型）→ 结构 + 文本模型
   · 01 科研项目申请书：10/11 → 11/11（补回“申请日期”）
   · 02 封面与表内下划线：3/3 → 3/3
   · 03 实验报告：36 个字段（含 7 个误报）→ 29/29，与人工清单完全一致
   · 开题申请表 23/23；项目任务书 86/90；开题报告书 11/11；开题结果报告 33/33
   · 类型修正示例：分数→数字、评语/任务分工/第N题程序分析→多行、实验日期→日期
   · 耗时：样张一约 12 秒；大任务书切成 4 片约 92 秒（旧切法 6 分钟且会被截断）
   · 模板要求仍只读文档自己的文字，截图读要求的分支已删除

Word 模板工作台 v5.12.0 · 识别准确度：基础信息归并 + 规范材料不误认
==========================================================

1）基础信息归并：填一次，写到所有位置

【v5.6.0 沿用】思考模型定标题

【本版新增】思考模型 qwen3:4b 负责“判断标题层级”
原来留着没用上的思考版 qwen3:4b（2.5GB），现在有了明确分工：
- 它只做一件需要“想”的事：通读文档段落，判断哪些是几级标题。
  这正是它的强项，也是指示版模型（以及原来的样式判定）做不好的地方。
- 解决的问题：自动排版页原来只认 Word 样式（Heading 1 / 标题 1 / 大纲级别），
  而学校模板里大量标题是**手动加粗放大**写的“假标题”，以前那一档根本命中不到。
- 双重判定，确保稳：
  · 带明确序号的（第一章 / 1.1 / 1.1.1 / 一、 / （一） / (1)）由内置规则**确定性**判定，不靠模型猜；
  · 没有序号、要看版式（字号更大、加粗、居中、段前后留白）的，交给思考模型判断；
  · 模型给出的编号还要过范围、文本长度、级别 1-3 的校验，宁可少标不乱标。
- 用法：导航「自动排版」→ 打开文档 → 左栏点「AI 识别标题层级（思考模型）」→
  模型判完自动重新应用排版，中栏立刻看到效果；状态栏会写“一级 N 个 · 二级 N 个 · 三级 N 个”。
- 实测（9 段样例：2 个章、2 个节、1 个小节、4 段正文，全部无 Word 标题样式）：
  判定 5/5 全中（含 12pt 与正文同字号的 1.1.1），耗时 91.4 秒；
  套用后 标题=黑体 16/14/12pt 居中/左对齐、正文=宋体 12pt 两端对齐，共 9 段全部落地。
- 代价与取舍：思考模型要“想”，首次约 1～2 分钟（比指示版慢很多，这正是它质量的来源）；
  结果只用于“确定哪些段是标题”，不生成任何正文，所以慢一点不影响内容安全。

三、两条使用路线（都在“模板制作”）
路线 A：v3.2 老流程（文档里已有 {{ }} 标记）
1. 保持 ai_runtime、ai_models 与本 exe 在同一目录（不要只拷 exe）。
2. 选 .docx → 点“小模型补全空标记名称”：给空的 {{ }} 区域按上下文补字段名（离线，约 20 秒/12 项）。
3. 自动接着识别 → 核对/改名 → “仅勾高置信” → “确认改名并录入模板库”。

路线 B：无占位符自动识别（任意 .docx，推荐新文档）
1. 选 .docx →（可选）勾选“视觉识别”；“按模板要求自动排版”无需勾选，识别时自动读取并照做。
2. 点“开始识别” → 核对字段 → 录入模板库。
3. 也可以直接把 .docx 拖到“填写生成”页任意位置，识别完立刻填写。

四、开关说明
- 视觉识别（唯一需要勾选的识别开关）：把页面截图交给 Qwen3-VL 等开源视觉模型，补充/校正填写位，
  并补读文本框、图片里的要求；不配置或取消勾选时自动跳过，结构识别照常工作。
- 按模板要求自动排版 + 删除说明搬提示：无勾选框，始终自动执行。
  离线也能读到大部分要求（靠底纹/颜色/关键词判断），勾上“视觉识别”覆盖面更全。
- 显示预览 / 实时渲染：在填写页顶部工具条和预览栏标题处；取消“实时渲染”回退原始模板参考图。

五、视觉模型怎么配（可选）
1. 顶栏“AI 设置”→“视觉模型（开源 VLM）”。
2. 预设：硅基流动 Qwen3-VL-32B（默认，开源权重）/ 阿里云百炼 qwen3-vl-plus / OpenRouter / 本机 Ollama / 自定义。
3. 填对应服务商的 API Key（与文本模型不同服务商时必须单独填），点“测试视觉”，通过后保存。
4. Key 只保存在本机 %LOCALAPPDATA%\LocalTools\WordTemplateTool\ai_config.json，不要发到聊天里。
5. 视觉识别发送的是“页面截图 + 栏目结构/要求文本”，不发送原始 .docx。

六、版式与页数
- 按说明改行距/缩进后，页数可能变化（模板自己也写了“保持整页设计”“不得跨页”这类互相牵扯的要求）。
- 实测：只填一项时页数不变（任务书 2→2、开题报告 2→2、工作情况记载表 10→10）；
  每个栏目都填上较长正文时可能多出页面（此前长文本实测 记载表 10→11、开题 2→3）。
- 生成完成的提示里会写出套用了多少段、删了多少条说明、当前预览页数；中栏预览可随时看整页效果。
- 版式一律按模板说明执行，已无关闭开关；如果你要“原文一字不动”的旧行为，
  请在录入模板前把说明文字改成普通正文色（去掉底纹/颜色），程序就不会把它当要求。

七、什么样的说明读不到
- 既没有底纹/颜色、也不含“宋体/行距/缩进/不少于/双面打印/手签”等关键词的纯黑提示句，
  离线读不到，会原样保留（宁可留着也不误删正文）。勾“视觉识别”让模型看图补读即可。
